# Design system plan

Preserve functional surfaces and consolidate only launch-critical inconsistencies. Web already has tokens and basic UI primitives; Flutter has a shared theme. The next audit must map usage before changing components.

Priority system contracts: readable type scale; spacing; high-contrast buttons; input labels/errors; cards and status badges; price breakdown; navigation; loading/skeleton/empty/error/retry; offline state; destructive-action confirmation; 44px-equivalent touch targets; reduced animation; Hindi/Marathi expansion tolerance.

Acceptance: the critical customer/merchant/delivery/admin paths use consistent states and terminology; pricing comes from authoritative quote/order values; no client-invented delivery fee; visual/device evidence exists for each critical screen.
